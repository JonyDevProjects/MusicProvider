# architecture
- For macOS builds that execute external binaries (e.g., yt-dlp via Rust FRB): disable App Sandbox by setting `com.apple.security.app-sandbox` to `false` in `DebugProfile.entitlements` (and `Release.entitlements` for non-App Store builds), otherwise `Command::new` fails with `Operation not permitted`. Confidence: 0.75
- Use Flutter Rust Bridge (FRB) for integrating yt-dlp natively into the mobile app, enabling shared Rust code with Nuclear's ecosystem. Confidence: 0.65
- For Rust cross-compilation to iOS (`aarch64-apple-ios`) with `zstd-sys`/C deps that fail on `___chkstk_darwin`: use `IPHONEOS_DEPLOYMENT_TARGET=15.0 cargo build --target aarch64-apple-ios --release` (`.cargo/config.toml` rustflags are overridden by the target's default `-target arm64-apple-ios10.0.0`). Confidence: 0.70
- When flutter_rust_bridge Rust lib is statically linked via CocoaPods on iOS (`.a` file), use `ExternalLibrary.process(iKnowHowToUseIt: true)` and add `s.static_framework = true` to the podspec instead of relying on default `.framework` loading. Confidence: 0.70
- Use an abstract `MusicService` interface with a strategy pattern: platform-specific implementations (`YtExplodeService` for iOS, `YtdlpNativeService` for macOS/Android, `ApiService` for web/fallback) plus a factory for selection by platform. Confidence: 0.80
- For Dart packages that don't compile on web (e.g., `youtube_explode_dart`), use conditional imports with a stub: barrel file with `import 'stub.dart' if (dart.library.io) 'impl.dart'` plus a factory function. Confidence: 0.75
- For testability of `PlayerProvider`, accept an injectable `List<MusicService>? services` parameter in the constructor rather than hardcoding service instances. Confidence: 0.70
- For iOS audio playback with YouTube CDN URLs that AVPlayer fails to open (error -1 / -11828), download the audio stream to a local temp file using Dart `http.Client` and play via `AudioSource.file` instead of `AudioSource.uri` with headers. Confidence: 0.80
- In iOS `Info.plist`, use `NSAllowsArbitraryLoads` (not `NSAllowsLocalNetworking`) to allow just_audio's AVPlayer proxy to fetch audio from external CDNs. Confidence: 0.85
- When selecting YouTube audio streams for iOS, prefer AAC/MP4 codecs (`mp4a.40.2`, `aac`) over WebM/Opus — iOS AVPlayer does not natively support WebM containers. Confidence: 0.85
- Avoid using Flutter `StreamBuilder` to read state from a broadcast stream (e.g., `onPlayerStateChanged`) that can emit critical events before the `StreamBuilder` first subscribes — during loading→playing transitions the event fires before the widget mounts, and broadcast streams don't replay, so the `StreamBuilder` defaults to a stale value. Instead, read the current value directly from the `ChangeNotifier` provider state and add an `onStateChanged` listener that calls `notifyListeners()` to keep the UI in sync. Confidence: 0.80
- When bundling Node.js/CJS plugins for a host runtime (e.g., Nuclear player plugins): use `tsup` as the bundler, mark runtime-provided dependencies as `external` (e.g., `@nuclearplayer/plugin-sdk`), and force non-allowlisted packages into the bundle via `noExternal` so they ship with the plugin. Confidence: 0.75
- Prefer zero `require()` calls in bundled output — plugins should be fully self-contained/autocontained without runtime `require()` calls to the host's module system. Confidence: 0.80
- Use `esbuildOptions.conditions` (e.g., `['browser']`) in tsup config to avoid bundling imports of Node.js builtins (e.g., `diagnostics_channel`) that don't exist in webview/renderer contexts. Confidence: 0.70
- Write core logic as generic functions with injectable dependencies (e.g., `resolveStreamInfo(videoId, fetchFn)` accepting any fetch function) so the same module can be reused across different execution contexts (standalone server vs plugin runtime) without coupling to a specific API. Confidence: 0.75
- Set `outExtension: () => ({ js: '.js' })` in tsup CJS config when the consuming host runtime expects a `.js` extension despite tsup 8.x defaulting to `.cjs` for CJS output. Confidence: 0.65
- When evaluating backend streaming solutions (HTTP proxy that pipes yt-dlp stdout to the device): cost-conscious about infrastructure costs — double bandwidth (source→backend→device) is a concern at scale; acceptable for personal/dev use but needs caching or a CDN for production viability. Confidence: 0.75
