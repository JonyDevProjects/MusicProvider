# spoti5-config
- Backend `baseUrl` in `api_service.dart`: detect by platform — `10.0.2.2:3000/api` for Android emulator, `localhost:3000/api` for iOS/Web/Desktop; use `Platform.isAndroid` with a `stub_io.dart` for web builds. Confidence: 0.90
- PlayerBar duration: always use `track.duration` from the backend (yt-dlp seconds) for the progress bar total, never `audioPlayer.duration` (just_audio may report double). Confidence: 0.95
- For fixing YouTube HTTP 403 on audio playback: use `AudioSource.uri` with headers (`User-Agent: Mozilla/5.0`) instead of `setUrl()`. Confidence: 0.90
- On iOS (which blocks `exec()` of external binaries), use `youtube_explode_dart` (pure Dart) as the primary music service via the Strategy Pattern. Confidence: 0.80
- audioplayers `UrlSource` does NOT support custom headers — header-based CDN-bypass solutions (e.g., `User-Agent: Mozilla/5.0`) are unavailable with audioplayers, unlike just_audio's `AudioSource.uri`. Confidence: 0.80
- On Android with audioplayers v6.x, calling `resume()` after `pause()` fails silently with `MEDIA_ERROR_UNKNOWN {what:-38}` (MediaPlayer server died); the native `MediaPlayer` enters an error state where `resume()` (seekTo+start) is a no-op. Work around by storing the playback URL in a field on first `play()` and calling `play(UrlSource(storedUrl))` instead of `resume()` — `play()` re-initializes the data source and recovers from error states. iOS AVPlayer handles `resume()` correctly, so this is Android-specific. Confidence: 0.85
- When using `play(UrlSource(storedUrl))` instead of `resume()` on Android (audioplayers v6.x), the fresh MediaPlayer starts from position 0 — seeking in the `.then()` callback after `play()` is too late (audio already started playing). Instead, attach `onPlayerStateChanged.where((s) => s == PlayerState.playing).first.then((_) => seek(pos))` listener BEFORE calling `play()` so the seek fires at the first `playing`-state transition, before audio data flows. Confidence: 0.85
- When capturing the paused position on Android with audioplayers, use a `_position` field updated by the `onPositionChanged` stream rather than reading `_audioPlayer.position` synchronously at pause time — the stream value is more reliable for resume position. Confidence: 0.80
